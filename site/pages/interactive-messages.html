Interactive messages

All methods are available through ctx.send.interactive and use the current chat as the recipient.

Native-flow support varies by WhatsApp client and version. In particular, WhatsApp Web/Desktop may show “This message couldn't load” for some native-flow message types even when the same message works on mobile. Test on the client your users actually use.

Quick replies

await ctx.send.interactive.quickReply({
  title: "Choose an action",
  body: "What would you like to do?",
  buttons: [
    { text: "Ping", id: ".ping" },
    { text: "Help", id: ".help" },
  ],
});

Button IDs are normalized as interactive responses and can reuse the normal command dispatcher.

Single select

await ctx.send.interactive.singleSelect({
  title: "Settings",
  body: "Choose a section.",
  selectLabel: "Open settings",
  sections: [
    {
      title: "General",
      rows: [
        { title: "Profile", description: "View your profile", id: ".profile" },
        { title: "Help", description: "Show help", id: ".help" },
      ],
    },
  ],
});

URL button

await ctx.send.interactive.urlButton({
  title: "Project",
  body: "Open the project website.",
  text: "Open website",
  url: "https://github.com/arsa0x/violajs",
});

Only absolute http:// and https:// URLs are accepted.

Call button

await ctx.send.interactive.callButton({
  body: "Need help? Contact support.",
  text: "Call support",
  phoneNumber: "+6281234567890",
});

Use an international-style phone number. The recipient's client decides how the call action is handled.

Image/video header

Any quick reply, single-select, URL, call, copy-code, location request, or in-app signup message can use an optional uploaded image/video header: 

await ctx.send.interactive.quickReply({
  body: "What would you like to do?",
  headerMedia: { type: "image", url: "https://example.com/banner.jpg" }, // or type: "video"
  buttons: [{ text: "Continue", id: ".continue" }],
});

The URL must be publicly reachable over HTTP(S). Baileys downloads and uploads the media before sending the interactive message.

In-app signup

await ctx.send.interactive.inAppSignup({
  title: "Create an account",
  body: "Continue with the in-app signup action.",
  footer: "violajs",
});

This sends the native-flow button name inapp_signup with an empty JSON parameter object. It is a low-level client action, not a full account-registration backend; actual behavior depends on WhatsApp client/account support.

Location request

Ask the recipient to share their current location:

await ctx.send.interactive.requestLocation({
  body: "Share your current location if you want to.",
  text: "Share location",
});

This uses the native-flow send_location action. Availability and presentation can vary by WhatsApp client and account type; test on the clients you intend to support.

Copy-code button

await ctx.send.interactive.copyCode({
  body: "Use this code at checkout.",
  text: "Copy code",
  code: "VIOLA10",
});

Quoting behavior

All methods quote the incoming message by default. Set quoted: false to send without quoting it.

Compatibility note

These methods construct WhatsApp native-flow messages through Baileys' relay API. Successful relay does not guarantee that every WhatsApp client can render the message. Keep a plain-text fallback for workflows where desktop support is required, and validate each new button type on mobile and Web/Desktop.

Carousel

A native carousel contains at least 2 image cards. The message can have a top-level footer, and each card can have its own footer. Each card accepts a buttons array with one or more native-flow buttons; button types can be mixed within a card, matching the Rust CarouselCard::buttons(...) builder. Supported variants are quick reply, URL, call, copy-code, and single-select. Image URLs must be publicly reachable so Baileys can download and upload each image to WhatsApp.

Quick-reply cards

await ctx.send.interactive.carousel({
  body: "Browse these projects.",
  footer: "Project carousel footer",
  cards: [
    {
      image: "https://example.com/project-one.jpg",
      title: "Project One",
      body: "A short project description.",
      footer: "First card footer",
      buttons: [
        { type: "quick_reply", text: "Details", id: ".project one" },
        {
          type: "url",
          text: "Open project",
          url: "https://example.com/project-one",
        },
      ],
    },
    {
      image: "https://example.com/project-two.jpg",
      title: "Project Two",
      body: "Another short description.",
      footer: "Second card footer",
      buttons: [{ type: "quick_reply", text: "Details", id: ".project two" }],
    },
  ],
});

URL cards

Each card can use one or more buttons, and button types do not need to match: 

await ctx.send.interactive.carousel({
  body: "Explore these links.",
  cards: [
    {
      image: "https://example.com/one.jpg",
      title: "First link",
      buttons: [{ type: "url", text: "Open", url: "https://example.com/one" }],
    },
    {
      image: "https://example.com/two.jpg",
      title: "Second link",
      buttons: [{ type: "url", text: "Open", url: "https://example.com/two" }],
    },
  ],
});

URL buttons accept optional merchantUrl and webviewInteraction (default true); copy-code buttons accept an optional id that defaults to the copied code. Single-select buttons use { type: "single_select", title, sections }. The previous singular button property remains supported for backward compatibility; new code should use buttons.

The carousel is built with Baileys' native carouselMessage structure. Native carousel rendering is client/version-dependent, so verify delivery and card actions on both WhatsApp mobile and Web/Desktop. Try the demo variants with .interactive carousel, .interactive carousel-url, .interactive carousel-call, .interactive carousel-copy, and .interactive carousel-list. .interactive signup tests inapp_signup, while .interactive media tests an image header.

The .interactive carousel command provides a test example.
